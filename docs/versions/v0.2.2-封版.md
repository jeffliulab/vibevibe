### 决策

- **粘贴键做成「窗口类名 → 键」的表,而不是「终端列表 + 一个终端键」**。
  因为 xterm 的粘贴是 `shift+insert` 而不是 `ctrl+shift+v` —— 一个列表加一个键
  表达不了这种差异
- **表里的默认值是各终端自己文档写明的键,不是我们逐个实测的**。注释里写清楚了。
  本项目只在 GNOME Terminal 上实测过,别把这张表说成"全部验证过"
- **查不到窗口类名一律退回默认键,绝不抛异常**。`xprop` 没装、Wayland、
  没有窗口获得焦点 —— 这些都只该影响"挑哪个键",不该让整次听写作废
- **`xprop` 算可选依赖**,不进 `Injector.check()`、不算 doctor 的 problem。
  缺了只是终端里粘不上,普通程序照常
- **修快捷键时只改 `command`,不碰 `binding`**。用户可能早就把组合键换成了别的,
  修一条死路径不该顺手把他挑的键位重置回默认
- **死路径的判据只看「可执行文件存不存在」**,不看命令串是否和我们会写的一致。
  用户可能自己加了参数或指着另一份安装 —— 宁可漏报,也别把手工调过的设置冲掉

### 踩过的坑

- **终端里 `Ctrl+V` 不是粘贴**,是 readline 的 `quoted-insert`(下一个字符按字面插入)。
  所以对着终端听写不只是"没反应",还会把你接下来敲的第一个键吃掉。
  而 VS Code 的集成终端里 `Ctrl+V` **恰好是**粘贴 —— 同一台机器上换个终端就时灵时不灵,
  这是它能一直没被发现的原因
- **`WM_CLASS` 有两个值**,instance 和 class,同一个终端两边写法可能完全不同
  (GNOME Terminal 是 `gnome-terminal-server` 和 `Gnome-terminal`)。
  只匹一个必漏,而且要大小写不敏感
- **TOML 的子表一开,上面那个表就关了**。`[inject.paste_key_by_window_class]`
  必须放在 `[inject]` 所有普通键之后,否则后面的 `restore_clipboard` 会算进子表里去;
  同一个 `[inject]` 头也不能写两遍
- **0.2.1 那个「登记过就跳过」的 bug 一共有三处,当时只修了一处**。
  快捷键那处从工作区改名(`8888-夏日大作战` → `8888-Projects`)当天起就是死的,
  而 `doctor` 一直报「一切正常」—— 体检照不出这类问题,等于没体检。
  这一版把三处收进 `launchers.py` 统一判断,并让 doctor 真正查它们
