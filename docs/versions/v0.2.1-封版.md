# v0.2.1 开发日志(已封版)

归档日期 2026-08-07 · git tag `v0.2.1` · PyPI 0.2.1

主题:托盘真退出 + 自启路径自愈

补丁版。v0.3.0 的两个主题(Wayland 注入、上下文偏置)一个没动。

## 2026-08-07

### 完成

- **托盘多一项「退出 vibevibe(停止服务)」**,点了之后守护进程和托盘一起没,
  内存全部还给系统。原有的「退出托盘(服务继续运行)」保留不动
- **命令行 `vibevibe quit`**,不依赖桌面环境的等价入口
- **新模块 `vibevibe/service.py`**:systemctl 封装和「彻底停」的逻辑收在一处,
  托盘、命令行、安装向导三处共用
- **自启文件路径失效时自愈**:`vibevibe setup` 会检查
  `~/.config/autostart/vibevibe-tray.desktop` 里的 `Exec=` 还指不指得到东西,
  指不到就重写

### 决策

- **「退出」= 停服务 + 关托盘,但不动开机自启**。等同于普通桌面应用的退出:
  这次会话不跑了,下次登录照常回来。真要永久停用,`systemctl --user disable
  vibevibe` 一条命令的事,没必要在菜单里再放一个容易点错的入口
- **`stop_all()` 两条路都走**:先 `systemctl --user stop`,再兜底发一次 IPC
  shutdown。因为守护进程有两种起法,只走一条都堵不死 ——
  systemd 起的那种,光发 IPC 没用(unit 里 `Restart=on-failure` 会把它拉回来);
  手动 `vibevibe daemon` 起的那种,systemd 根本不认识它
- **守护进程停不干净也照样退出托盘**。先弹框说明原因,再 `Gtk.main_quit()`。
  一个点了不退的「退出」按钮,正是这个版本要修的问题本身
- **`service.py` 不许 import GTK**。`cli.py` 要用它,而命令行必须能在没有桌面的
  环境里跑 —— 这是把这几十行从 `tray.py` 抽出来的唯一理由

### 踩过的坑

- **「文件在 = 已装」是个假判断**。`step_tray()` 原来只看
  `~/.config/autostart/vibevibe-tray.desktop` 存不存在,存在就报"已装"。
  但 `.desktop` 里的 `Exec=` 是**绝对路径**(必须如此,自启时的 PATH 跟终端不一样),
  项目目录一改名它就变成指向空气的死链接,而文件还在原地 ——
  于是"已装"报了一整天,托盘其实早就起不来了。本机实例:工作区
  `8888-夏日大作战` 改名 `8888-Projects` 之后,unit 和 venv 都跟着修了,
  唯独这个文件没人动
- **面板上那个托盘图标可能是个僵尸**。同一次改名之后,7/30 从旧路径起的托盘进程
  一直活着(`/proc/<pid>/maps` 里 18 条 `(deleted)`),它的图标目录随旧路径一起消失,
  所以面板上要么是坏图标要么什么都没有 —— 这也是「找不到退出按钮」的直接原因之一。
  升级时必须先 kill 掉旧进程再起新的,否则两个托盘会同时挂着
