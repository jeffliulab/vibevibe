# v0.2.0 开发日志(已封版)

归档日期 2026-07-26 · git tag `v0.2.0` · PyPI 0.2.0

主题:两键小键盘接入 + 双触发通道 + 热键冲突检查

## 2026-07-26

### 完成

- **小键盘接入**(T TYPEKEY Z2 / 544b:5a32 / CH55xQMKLite 固件)
  - 用 VIA 协议直接改键位:左键 → KC_F19,右键 → KC_ENTER
  - udev 规则用 `TAG+="uaccess"`,只针对这一个 VID:PID
- **双触发通道**,同时生效
  - `[hotkey]` evdev 直读,固定 KEY_F19,对应小键盘左键
  - `[shortcut]` 桌面快捷键,默认 `<Super><Shift>v`,零权限零硬件
- **热键冲突检查**:撞车的直接拒绝,有副作用的提醒
- 设置界面加「按键」页,支持**按下即捕获**(含组合键)
- 触发来源记进日志,能分清是小键盘还是快捷键触发的
- 托盘异常不再静默,日志写到 `~/.local/state/vibevibe/tray.log`

### 决策

- **grab 独占必须关掉**。原计划把"能整个独占设备"当成专用小键盘的
  核心优势,两键布局推翻了它:独占是**整设备级**的,会把右键的 Enter
  一起吞掉。不独占也没事 —— F19 在 X11 里没有 keysym,漏给应用无副作用
- **默认快捷键选 `<Super><Shift>v` 而不是 `Ctrl+Shift+V`**。后者在
  浏览器/VS Code/终端里都是「粘贴为纯文本」,而这类**应用内部**的占用
  gsettings 根本查不出来。应用基本不碰 Super(桌面环境保留键),所以最安全
- **hotkey.key 固定 F19**:小键盘固件里也烧成 F19,换任何电脑插上都能用

### 踩过的坑

- **安全闸判据是错的**:原来用"按键数超过 8 就拒绝独占"防止误配到主键盘。
  实测两键小键盘声明 **279 个键**、比主键盘(143)还多 —— QMK 系固件不管
  物理几个键都声明整个键位范围。已改成设备名匹配
- **冲突检查器漏报**:GNOME 的加速器字符串没规范化,`<Shift><Super>space`
  和 `<Super><Shift>space` 是同一个组合却匹配不上;`<Primary>`/`<Ctrl>`/
  `<Control>` 三种别名也没归一。已加规范化
- **冲突检查器误报可用**:输入"乱写的"三个字返回"✓ 可用",因为没校验主键
  是不是合法 keysym 名。已加校验
- **推荐值被自己的数据打脸**:提示里写死"推荐 F13~F24",实测这台机器上
  F13~F18 是 XF86Tools/Launch5~9、F20~F23 是音量和触摸板,**十二个里只有
  F19 和 F24 是空的**。改成按当前布局现算
- **设置打不开**:托盘跑着一天前的旧代码,不认识新配置项,`load_config()`
  抛异常而 stderr 被 `>/dev/null` 丢掉,表现为"点了没反应"
